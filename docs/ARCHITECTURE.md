# Architecture Blueprint (Lightweight Feature-First)

## 1. Architectural Philosophy

This application is an **offline-first, single-machine desktop app** backed by a local SQLite database.  
Following our **Simple Feature-First (Lightweight)** architecture:
- **No unnecessary layers**: We do **not** use `UseCase` classes, `Either<Failure, T>` wrappers, DTO-to-Entity mappers, or network repositories.
- **Drift is the single source of truth**: UI features observe reactive `Stream`s or invoke `Future` methods directly on `AppDatabase` (or thin feature services for multi-step operations like Excel Smart-Merge, PDF generation, and `.zip` backup/restore).
- **Centralized Design System**: All colors, typography (`Cairo`), spacing, bilingual strings (`ar`/`fr`), and shared widgets (`AppPanel`, `StatusBadge`, `AlgerianEmblemSvg`, `BloodHeartLogoSvg`) live in `lib/core/`.

## 3. Local SQLite Schema (Drift)

### Table 1: `donors`
| Column | SQLite Type | Constraints / Notes |
| :--- | :--- | :--- |
| `id` | `TEXT` | `PRIMARY KEY` (UUID v4) |
| `name` | `TEXT` | `NOT NULL` (Indexed for fast search) |
| `gender` | `TEXT` | `NOT NULL` (`'M'` or `'F'`) |
| `blood_group` | `TEXT` | `NOT NULL` (`'A+'`, `'A-'`, `'B+'`, `'B-'`, `'AB+'`, `'AB-'`, `'O+'`, `'O-'`) |
| `phone` | `TEXT` | `NOT NULL DEFAULT ''` (Indexed for search & smart-merge matching) |
| `address` | `TEXT` | `NOT NULL DEFAULT ''` |
| `birth_date` | `TEXT` | `NOT NULL DEFAULT ''` (`YYYY-MM-DD` or `''`) |
| `last_donation` | `TEXT` | `NOT NULL DEFAULT ''` (`YYYY-MM-DD` or `''`) |
| `last_test` | `TEXT` | `NOT NULL DEFAULT ''` (`YYYY-MM-DD` or `''`) |
| `notes` | `TEXT` | `NOT NULL DEFAULT ''` |
| `photo_filename` | `TEXT` | `NOT NULL DEFAULT ''` (Relative filename inside `photos/`, e.g. `<id>.jpg`) |
| `donation_count` | `INTEGER` | `NOT NULL DEFAULT 0` |
| `created_at` | `TEXT` | `NOT NULL` (ISO-8601 timestamp) |
| `updated_at` | `TEXT` | `NOT NULL` (ISO-8601 timestamp) |

### Table 2: `donation_events`
Tracks historical donations and blood tests per donor:
| Column | SQLite Type | Constraints / Notes |
| :--- | :--- | :--- |
| `id` | `TEXT` | `PRIMARY KEY` (UUID v4) |
| `donor_id` | `TEXT` | `NOT NULL REFERENCES donors(id) ON DELETE CASCADE` |
| `event_type` | `TEXT` | `NOT NULL` (`'donation'` or `'test'`) |
| `event_date` | `TEXT` | `NOT NULL` (`YYYY-MM-DD`) |
| `notes` | `TEXT` | `NOT NULL DEFAULT ''` |
| `created_at` | `TEXT` | `NOT NULL` (ISO-8601 timestamp) |

**Transactional Invariant**:
Whenever a user clicks **"Mark Donated Today"** (`تسجيل تبرع اليوم`) or updates `last_donation` / `last_test` to a new date:
1. Insert a record into `donation_events` (if one doesn't already exist for `(donor_id, event_type, event_date)`).
2. Recompute `last_donation`, `last_test`, and `donation_count` on the parent `donors` row inside the **same SQLite transaction**.

### Table 3: `app_settings` (Single-Row Configuration)
| Column | SQLite Type | Default Value |
| :--- | :--- | :--- |
| `id` | `INTEGER` | `PRIMARY KEY CHECK (id = 1)` |
| `username` | `TEXT` | `'admin'` |
| `password_hash` | `TEXT` | SHA-256 hash of `'admin'` + salt |
| `is_default_password` | `INTEGER` | `1` (Hides `"Default: admin / admin"` hint once changed) |
| `language` | `TEXT` | `'ar'` (`'ar'` or `'fr'`) |
| `notifications_enabled` | `INTEGER` | `1` |
| `notified_json` | `TEXT` | `'{}'` (Map of `donorId -> lastReferenceDateNotified`) |

## 5. Data Migration & Smart-Merge Flows

### Flow A: Smart-Merge Excel Import (`.xlsx` / `.csv`)
1. **Pre-Import Safety**: Automatically trigger a silent `.zip` snapshot in `backups/` before running bulk import.
2. **Parse Sheet 1 (`Donneurs`)**:
   - Normalize `phone` by stripping spaces/dashes (`0551 23 45 67` → `0551234567`).
   - Normalize `name` by trimming and collapsing whitespace.
   - Parse dates flexibly: Excel serial numbers (`45210`), `DD/MM/YYYY`, `DD-MM-YYYY`, or `YYYY-MM-DD` → normalized to `YYYY-MM-DD`.
3. **Deduplication / Upsert Rule**:
   - Look up existing donor by:
     1. Non-empty normalized `phone` match, **OR**
     2. Case-insensitive `name` + `blood_group` match (if phone is empty).
   - **If match found**:
     - Keep `max(existing.lastDonation, imported.lastDonation)` and `max(existing.lastTest, imported.lastTest)`.
     - Fill any blank fields (`address`, `birthDate`, `phone`, `notes`) from the imported row.
     - Append any new donation/test dates to `donation_events`.
   - **If no match**:
     - Insert new donor row + initial `donation_events` rows if `lastDonation`/`lastTest` are present.
4. **Parse Sheet 2 (`Historique`, if present in exported `.xlsx`)**:
   - Merge historical events by `(donor_phone_or_name, event_type, event_date)` without duplicating.

### Flow B: Full PC-to-PC Migration (`.zip` Backup & Restore)
- **Export Backup**: Runs `VACUUM INTO` a temporary SQLite file (safe even while DB is open), packages that `.sqlite` file + the `photos/` folder into `cwts_setif_backup_YYYY-MM-DD.zip`.
- **Restore Backup**: Validates that the `.zip` contains a valid SQLite database with the `donors` table, creates an automatic safety backup of the current state in `backups/`, replaces the active database & `photos/`, and reloads the UI.
